# 2026 主持人大赛投票系统

小组赛 / 个人赛双入口投票 + 密码条双权限 + 自动计分排名 + 全过程可复核导出。
Node.js + Fastify + SQLite（Node 内置 `node:sqlite`，**零原生依赖**，服务器无需编译任何东西）。

---

## 一、功能一览

### 前台（投票）
| 路径 | 用途 |
|---|---|
| `/vote/group` | **小组赛**投票入口（独立 URL） |
| `/vote/individual` | **个人赛**投票入口（独立 URL） |
| `/board` | 排名公示榜 —— **严格由后台开关控制**：未开启时任何人（含管理员）访问都返回 403 |
| `/manage/board` | 管理员专用的公示榜预览（投屏可用），不受开关影响 |
| `/logout` | 退出登录（中性结束页，无任何入口链接） |
| `/healthz` | 健康检查（JSON） |
| `/` | **刻意返回 404** —— 不提供统一的入口选择页 |

> **公示榜的开关是硬开关**：`/board` 完全由「系统设置 → 向公众开放排名公示榜」决定，
> 未开启时即使已登录管理员访问也返回 403（管理员预览请用 `/manage/board`）。
>
> **两个投票部分相互隔离**：系统内不出现任何「小组赛 ↔ 个人赛」的跳转链接，
> 投票页、完成页、状态页、退出页都不含另一个部分的入口；根路径也直接返回 404。
> 每个部分只能通过现场对应的入口 URL / 二维码进入（登录状态两者共用，同一张密码条照常各投一次）。

- **登录方式**：输入密码条。密码条即身份凭证，一人一条，并在后台绑定权限类型。
- **两种权限**：`大众评审`（勾选 3 位选手投票，可少选不可多选）／`专业评审`（对每位选手打 0-100 分）。
- 同一条密码条可在小组赛与个人赛**各投一次**；两个赛事数据完全隔离。
- 投票页移动端优先：卡片式选手列表、勾满后其余自动置灰、底部固定提交按钮、二次确认。
- 专业评审打分页：10 位选手数字输入、进度条、草稿本地保存、截止前可重复提交修改。

### 后台（`/manage`）
| 页面 | 功能 |
|---|---|
| 仪表盘 | 实时统计、赛程状态、快捷开关、最终总排名、最近操作 |
| 选手管理 | 10 位选手的姓名/序号/标签/简介/照片（上传自动替换）、启用停用、排序 |
| 密码条管理 | **一键同时生成大众 + 专业评审密码条**（可设定数量、自动编号）、绑定评审席、启用停用、**重置单张投票状态**、搜索、打印页（**自动分栏分页排版**，可选 1-3 列与字号）、导出清单 |
| 投票数据 | 查看全部投票记录（含 IP、UA、时间、来源）、修改投给谁、作废/恢复、彻底删除 |
| 打分数数据 | 4 位评审 × 10 位选手打分总表、批量修改、单格清空（恢复「未评」） |
| 手动赋分 | 手动新增投票、为某位选手批量补 N 票、手动录入/覆盖评审分数，**均支持「改前 → 改后」排名影响预览** |
| 赛程与开关 | 两个赛事独立设置开始/截止时间、一键开启/截止/重开，截止后自动锁定并统计 |
| 结果与排名 | 小组赛、个人赛、最终总成绩三张表 + 当前生效规则说明 + 强制重算 |
| 数据导出 | 全量数据与计分过程 / 仅排名表 / 密码条清单 |
| 操作日志 | 全部人工操作的前后快照，可按动作与关键字筛选，支持导出 |
| **数据清空** | 一键清空小组赛/个人赛的投票记录与评审打分（可分别勾选），**需输入当前管理员密码二次确认**；用于删除测试数据或赛前重置 |
| 系统设置 | 赛事信息、主题色、投票与打分规则、权重与上限、并列与缺评规则、安全设置、管理员账号管理 |

### 后台操作「不跳转」
后台所有按钮（生成密码条、开启/截止、手动赋分、修改数据、调整设置…）都采用**原地提交**：
点击后在右下角浮出结果提示，并只局部刷新受影响的区块，**不会跳转或整页刷新**，输入的内容也不会被清空。
（浏览器禁用 JS 时会自动回退为传统的「提交后重定向」方式，功能不受影响。）

### 计分规则（后台可改参数）
```
大众评审：每人勾选 3 位 → 票数 → 原始排名 → 赋分（第1名10分，逐名递减，第10名1分；0票得0分）
          并列：取最优名次，后续名次跳过（两人并列第2 ⇒ 下一名为第4）
专业评审：4 位评审百分制打分 → 算术平均分（缺评默认按实际提交人数求平均）

赛事得分 = 专业评审平均分 (0-100) + 大众评审赋分 (1-10)     上限 110
最终总成绩 = 小组赛得分 × 40% + 个人赛得分 × 60%
```

### 导出的「透明性」
`/manage/export/full` 生成的 Excel 含 **11 个工作表**，结论与推导过程并列，可手工复算任意一个数字：

1. `最终总排名`（结论）
2. `说明与规则`（导出当时的全部参数与公式）
3. `小组赛-计分过程` ①票数 ②原始排名 ③赋分 ④各评审打分 ⑤有效评审数 ⑥合计 ⑦除数 ⑧平均分 ⑨封顶前 ⑩上限 ⑪最终得分
4. `个人赛-计分过程`（同上）
5. `总成绩计算过程`（加权乘数与加权值逐项列出）
6. `原始数据-大众投票明细`（每条记录：谁的密码条、几点、IP、浏览器、投给谁、是否被改过）
7. `原始数据-专业评审打分`（每一格分数、来源、录入人、时间）
8. `原始数据-密码条清单`（含投票状态）
9. `原始数据-选手名单`
10. `操作日志`（全部增删改的前后快照）
11. `统计摘要`

## 二、本地运行

```bash
npm install
HV_ADMIN_PASS='你的初始密码' npm start     # 默认 http://127.0.0.1:3000
```

首次启动会自动：
1. 建库建表；
2. 创建 10 位选手占位数据（请在后台改成真实姓名并上传照片）；
3. 生成 4 条专业评审密码条（绑定评审席 1-4）与 20 条大众评审密码条，写入 `data/INITIAL_CODES.txt`；
4. 创建管理员账号，初始密码写入 `data/INITIAL_ADMIN.txt`。

其他命令：
```bash
npm test                      # 计分引擎单元测试
node scripts/e2e.mjs          # 端到端验收（需服务已启动）
node scripts/screenshot.mjs   # 抓取各页面截图（需本机 Chrome）
node scripts/backup.mjs       # 手动备份一次
node scripts/reset-data.mjs --yes          # 清空运行数据（保留选手与密码条）
node scripts/reset-admin.mjs  # 重置管理员密码 / 解锁
node scripts/loadtest.mjs     # 并发压测（自动造数据并清理，需在服务器上运行）
node scripts/verify-flow.mjs  # 投票/打分链路自检（自动造数据并清理）
```

## 三、部署（远程服务器）

```bash
./deploy/deploy.sh bootstrap   # 首次：安装 Node/Nginx、建用户与目录、写配置
./deploy/deploy.sh push        # 发布：上传代码、npm ci、重启服务、自动验收
./deploy/deploy.sh verify      # 仅做验收检查
./deploy/deploy.sh logs        # 查看日志
./deploy/deploy.sh backup      # 立即备份
```

### 目录结构（服务器）
```
/opt/hostvote/
├── app/          # 代码（可被覆盖升级）
├── data/         # SQLite 数据库 + uploads/ 选手照片 + INITIAL_*.txt
├── backup/       # 每日自动备份（保留 14 份）
└── logs/         # app.log / app.err.log / backup.log
```

### 双端口访问
应用只监听 `127.0.0.1:3000`，由 Nginx 同时监听 **80** 与 **8080** 反向代理到同一应用 ——
两个端口访问的是**同一套系统、同一份数据**（现场可任选其一，或用 8080 作为备用入口）。

### 常用运维命令
```bash
systemctl status hostvote          # 服务状态
systemctl restart hostvote         # 重启
journalctl -u hostvote -f          # 实时日志（也可 tail /opt/hostvote/logs/app.log）
tail -f /var/log/nginx/hostvote-access.log
nginx -t && systemctl reload nginx # 校验并重载 Nginx
ls -la /opt/hostvote/backup        # 查看备份
```

### 恢复备份
```bash
systemctl stop hostvote
cp /opt/hostvote/backup/hostvote-YYYYMMDD-HHMMSS.db /opt/hostvote/data/hostvote.db
rm -f /opt/hostvote/data/hostvote.db-wal /opt/hostvote/data/hostvote.db-shm
chown hostvote:hostvote /opt/hostvote/data/hostvote.db
systemctl start hostvote
```

## 四、容量与性能（实测）

在真实服务器（1 核 / 1.8GB / Debian 12）上，用 200/500/1000 个虚拟用户**同时**执行完整流程
（扫码 → 输密码 → 勾选 3 人 → 提交 → 完成页）的实测结果：

| 并发用户 | 请求数 | 失败 | 总耗时 | p50 | p95 | 最慢 |
|---|---|---|---|---|---|---|
| **200** | 1000 | **0** | 1.6 s | 6 ms | 1.2 s | 1.5 s |
| 500 | 2500 | **0** | 3.4 s | 5 ms | 2.6 s | 3.3 s |
| 1000 | 5000 | **0** | 6.8 s | 5 ms | 5.1 s | 6.7 s |

- 服务器处理能力约 **730 请求/秒**（单核），200 人完整投票共 1000 个请求；
  现实中大家是几十秒内陆续扫码，实际负载仅几请求/秒，CPU 占用不到 3%。
- 内存：跑完 1000 并发后常驻 133 MB、峰值 167 MB（总内存 1806 MB）。
- **结论：200 人规模完全不需要升级服务器**，1000 人同时提交也零失败。

复测方法（任何时候可自己跑，脚本会自动造数据并在结束后完整清理、还原赛程）：
```bash
cd /opt/hostvote/app
BASE=http://127.0.0.1:80 USERS=200 PHASE=full node scripts/loadtest.mjs
```

### 注意：密码条数量要够
每位大众评审需要**一条**密码条。若预计 200 人投票，请先在
「密码条管理 → ⚡ 一键生成密码条」把**大众评审数量**改成 ≥200 再生成（选择「追加生成」即可）。

## 五、现场使用流程建议

1. **赛前准备**
   - `选手管理`：录入 10 位选手真实姓名并上传照片（建议竖版，比例 3:4）。
   - `密码条管理`：在「⚡ 一键生成密码条」里填好 **大众评审数量**（如 60）与 **专业评审数量**（4），
     点一下即可同时生成两套并自动编号；再到打印页选好列数与字号，打印裁剪后发放。
   - `系统设置`：确认 `大众可勾选人数=3`、`第1名赋分=10`、`评审席位数=4`、`上限=110`、`权重 0.4/0.6`。
2. **开赛**：`赛程与开关` 设置开始/截止时间并开启；
   把 `http://<服务器IP>/vote/group` 与 `http://<服务器IP>/vote/individual` **分别**生成二维码，
   在对应环节的现场海报上只放对应那一张（两个部分在系统内互不可见，所以二维码就是唯一的入口）。
3. **比赛期间**：`投票数据` 实时看票；`手动赋分` 处理纸质票与临时情况（有改前/改后预览）。
4. **截止**：到点自动锁定并统计；也可点「立即截止并统计」。
5. **公布**：`结果与排名` 或 `/board` 展示；`数据导出` 一键导出 Excel 归档。
6. **赛后**：保留 `/opt/hostvote/backup` 中的备份与导出的 Excel。

## 六、安全与可靠性设计

- 密码条、管理员密码均哈希存储（bcrypt）；会话为服务端随机 256 位 sid，浏览器 Cookie 不含任何可伪造信息，**服务重启不掉线**。
- 后台连续 5 次密码错误锁定 1 小时（阈值与时长可配），可在后台手动解锁。
- 因现场大量用户共用校园网出口 IP，**不做 IP 级封禁**；密码条登录仅做宽松限流
  （同一 IP 默认 5000 次 / 5 分钟，可在「系统设置」中调整；生产环境当前设为 10000 次 / 5 分钟）。
  密码条为 8 位、32 字符集（约 1.1 万亿种组合），暴力枚举本身不可行。
- 所有写接口服务端强校验：赛事开关与时间窗、勾选人数上限、分数范围、重复投票、权限类型。
- Cookie `HttpOnly` + `SameSite=Lax`，并对带 Origin 的写请求做同源校验。
- 任何人工改动都写入操作日志（谁、何时、改了什么的完整前后快照）。
- SQLite WAL 模式 + 事务（`BEGIN IMMEDIATE`）保证并发投票不丢票、不重复。
- 每日 02:00 自动备份数据库与照片，保留最近 14 份。

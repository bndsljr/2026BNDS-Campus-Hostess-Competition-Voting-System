# 2026 主持人大赛投票系统 — 功能大纲 & 技术大纲

> 版本 v1.0（待确认）｜文档状态：需求评审中
> 规模：10 位选手 · 4 位专业评审 · 大众评审若干
> 核心目标：两套隔离投票入口 + 自动计分排名 + 一键导出 + 双端口访问

---

## 第一部分：功能大纲

### 0. 角色与权限总览

| 角色 | 入口 | 认证方式 | 核心能力 |
|---|---|---|---|
| 大众评审 | `/vote/group`、`/vote/individual` | 共用密码条（普通用户登录） | 勾选 3 位选手投票（可少选，不可多选） |
| 专业评审 | `/vote/group`、`/vote/individual` | 共用密码条 + 评审身份确认 | 对 10 位选手分别打 0–100 分 |
| 管理员 | `/manage` | 独立账号密码 | 全量数据、用户、赛程、手动赋分、导出、日志 |

- 普通用户**只能**从两个投票入口进入，无任何后台入口暴露（`/manage` 不在投票页出现任何链接）。
- 两套入口共用同一个密码条；同一密码条可分别在小组赛、个人赛各投一次（两套独立投票记录）。

---

### 1. 认证与访问控制模块

**1.1 密码条管理（后台）**
- 生成方式：一键随机生成（可设长度/字符集，默认 8 位易读字符，去除 0/O/1/I 等易混字符）；也支持管理员自定义设置。
- 密码条为**全局单条**（两套入口共用），可随时重置；重置后旧会话失效策略可选（默认：已登录会话保留，新登录用新密码）。
- 支持设置密码条有效期（可选，默认关闭）。
- 密码条可一键复制、一键打印（现场发放用）。

**1.2 普通用户登录**
- 页面：极简卡片式，仅一个大输入框 + "进入"按钮，手机端优先。
- 校验成功后写入签名会话 Cookie（HttpOnly、SameSite=Lax、有效期可配，默认 12 小时）。
- 登录成功后**直接进入当前入口对应页面**（不存在入口选择页）：
  - 小组赛入口 `/vote/group`（独立 URL、独立二维码）
  - 个人赛入口 `/vote/individual`（独立 URL、独立二维码）
- **两部分相互隔离（2026-10-09 需求确认）**：系统内不提供任何跨部分跳转，
  根路径 `/` 直接返回 404；某一环节进行时，选手不会在页面里看到另一环节的入口。
  登录状态两者共用，同一张密码条仍在两个入口各可投票一次。
- 身份选择：登录后选择/确认本次身份（大众评审 / 专业评审），用于后续计分归类。
- 频率限制：同一 IP 登录失败限流（防暴力破解），默认 10 次/分钟。
- 赛事状态感知：对应赛事未开启显示"投票尚未开始"，已截止显示"投票已结束，感谢参与"。

**1.3 管理员登录**
- 路径 `/manage`，账号 + 密码（bcrypt 存储）。
- 初始账号密码在部署完成时交付：默认 `admin` / 随机强密码（部署时生成并打印到部署报告，不写死在代码里）。
- 支持修改密码、新增管理员账号、会话闲置超时（默认 2 小时）。

---

### 2. 后台管理面板（`/manage`）

**2.1 仪表盘**
- 小组赛 / 个人赛 各自：投票开关状态、已投票人数、专业评审提交进度（x/4）、实时排名榜。
- 一键"重新计算"按钮（强制重算排名与赋分）。

**2.2 投票数据查看**
- 按赛事分页查看每一条投票记录：投票人标识、身份、IP、时间、所投选手 / 所打分数。
- 支持按选手、身份、时间范围筛选、搜索。

**2.3 投票数据修改**
- 可编辑单条记录（改所投选手、改分数），可作废单条记录（软删除，保留审计）。
- 修改后自动触发该赛事重算 + 排名刷新。
- 每一次修改写入操作日志（谁、何时、改了什么、改前改后）。

**2.4 用户（投票人）管理**
- 投票人名单维护：批量导入（粘贴/Excel）、新增、编辑、停用、删除。
- 大众评审名单用于登录后身份选择与"一人一票"校验（见 2.8 待确认项）。
- 专业评审名单（4 位）在此维护：姓名、顺序编号，用于打分页身份归属。
- 每个投票人的投票状态一览：小组赛已投/未投、个人赛已投/未投。

**2.5 选手管理**
- 10 位选手的：编号/序号、姓名、图片（上传，自动压缩与裁剪为统一比例）、所属小组/标签（可选）、简介（可选）。
- 支持排序拖拽、启用/停用（停用选手不显示在投票页，但历史数据保留）。
- 选手图片统一存放 `data/uploads/`，投票页自动生成缩略图，手机端友好。

**2.6 手动赋分专用页面**
- 场景：线下补录、纸质表录入、临时加票。
- 功能：
  - 手动新增一条"大众评审投票"（选择 3 位选手 / 或直接指定给某几位选手加票数）。
  - 手动新增/覆盖某位专业评审对某选手的分数。
  - 现场打分快速录入表格：4 行评审 × 10 列选手 = 40 格，键盘 Tab 连续录入。
- 所有手动录入标记来源为 `manual`，并强制填写备注 + 记录操作人。
- 录入后实时预览"重算后的排名与赋分变化"（改前 / 改后对比），确认后落库。

**2.7 赛程与开关控制**
- 小组赛：开始时间、截止时间（精确到分钟）、手动开启 / 手动截止 / 重新开启。
- 个人赛：同上，两套完全独立。
- 截止自动生效：到达截止时间后系统自动锁定（后端强校验，非仅前端隐藏），并自动执行一次完整统计。
- 倒计时展示在投票页顶部。

**2.8 导出**
- 一键导出 Excel（`.xlsx`）：
  - 明细表：选手姓名、小组赛大众投票赋分、小组赛专业评审平均分、小组赛总分、个人赛大众投票赋分、个人赛专业评审平均分、个人赛总分、最终总成绩、最终总排名。
  - 附加 sheet（可选）：大众评审原始票数与原始排名、4 位专业评审原始打分、修改日志。
  - 一键"仅排名"导出：仅两列 —— 姓名、最终排名。
- 导出文件名带时间戳，中文不乱码（UTF-8 + BOM / 原生 xlsx）。

**2.9 操作日志（审计）**
- 记录：登录成功/失败、密码条变更、开关赛程、投票记录增删改、手动赋分、选手信息变更、数据导出。
- 字段：时间、操作人、动作类型、对象、变更前、变更后、IP。
- 支持按类型/时间筛选、导出日志。

### 3. 模块一：小组赛计分规则

**3.1 大众评审（投票制）**
- 规则：从 10 位选手中**勾选 3 位**（不可超过 3 位；可少于 3 位），提交后锁定。
- 提交前二次确认，提交后同一身份不可重复投票（管理员可在后台重置该投票人状态）。
- 截止后自动统计全部投票，得到每位选手的**大众评审原始票数**，据此生成**原始排名**。
- 排名赋分：第 1 名 10 分、第 2 名 9 分 …… 第 10 名 1 分。
- 并列处理（默认方案，待确认）：票数相同者取**并列最优名次**的赋分（例如两人并列第 2，均得 9 分，下一名按第 4 名计 7 分）。
- 管理员可后台手动增加/调整票数，保留操作日志；修改后自动**重新计算排名与赋分**。

**3.2 专业评审（百分制）**
- 4 位专业评审，每位对 10 位选手分别打 0–100 分（支持小数点后一位，可选）。
- 选手专业评审平均分 = 4 位评审分数之和 ÷ 4（满分 100）。
- 缺评处理（待确认）：默认按"实际已提交评审数"求平均（例如仅 3 位提交则 ÷3），并在后台高亮提示缺评；管理员可切换为"缺评按 0 分计入 ÷4"。

**3.3 小组赛总分**
```
小组赛得分 = 专业评审平均分（0–100） + 大众评审赋分（1–10）
上限 110 分（100 + 10）
```
- 未获得任何大众票的选手：赋分 0 分（待确认，默认 0）。

---

### 4. 模块二：个人赛计分规则

- 计分逻辑与小组赛**完全一致**，拥有**独立数据体系**（独立投票记录表、独立打分表、独立开关、独立排名）。
- 大众评审：选 3 人投票 → 原始票数 → 原始排名 → 赋分 1–10 分。
- 专业评审：4 位评审百分制打分 → 算术平均分。
- 管理员手动干预：同小组赛。
```
个人赛得分 = 个人赛专业评审平均分 + 个人赛大众评审赋分
上限 110 分
```
- 与小组赛数据**相互隔离、互不干扰**：一套数据的修改不触发另一套重算。

---

### 5. 模块三：最终总成绩

```
总成绩 = 小组赛得分 × 40% + 个人赛得分 × 60%
```
- 保留 2 位小数（可配），系统自动计算每位选手最终总成绩并生成完整总排名。
- 总成绩并列处理（待确认）：默认按"个人赛得分高者优先"打破平局，仍相同则按专业评审平均分高者优先。
- 任何单项数据变更后，总榜自动重新计算，后台可见实时总排名。

| 导出项 | 内容 | 格式 |
|---|---|---|
| 全量总表 | 姓名、小组赛（大众赋分 / 专业均分 / 总分）、个人赛（大众赋分 / 专业均分 / 总分）、最终总成绩、最终排名 | `.xlsx` |

### 7. 前端体验要求

- 风格：简约美观、留白充足、主色调可后台配置（默认深蓝 + 金），大字号、高对比度，现场投影与手机均清晰。
- 投票页**移动端优先**：卡片式选手列表（头像 + 姓名 + 勾选框），单列布局，底部固定"提交"按钮，勾满 3 位后其余项自动置灰。
- 专业评审打分页：10 位选手卡片 + 数字输入（大数字键盘友好），可保存草稿、整页提交，提交前校验全部填写。
- 排名公示页（可选，可开关）：现场投屏用大屏榜单，只显示名次与姓名。
- 无需登录的静态页面：无（除健康检查）。

### 8. 待确认事项（需你拍板，我会按默认值实施）

1. **大众评审如何区分身份（最关键）**
   共用密码条无法天然区分"谁投的票"，会影响"一人一票"。三种方案：
   - A（推荐）：登录后从后台预置的**大众评审名单中选自己名字**，同一名单项在每个赛事只能投一次 → 一人一票 + 可核对。
   - B：登录后仅填姓名（自由输入），按姓名去重 → 灵活但可写错名/重复名。
   - C：不做身份识别，仅靠密码条 + IP/设备本地限制（现场信任模式），后台只看票数。
2. **专业评审身份确认**：登录后选择"我是专业评审 X（姓名）"，后台可见 4 人各自提交进度；是否允许评审在截止前**修改**自己已提交的分数？
3. **并列排名赋分规则**：默认"并列取最优名次赋分，后续名次跳过"。
4. **专业评审缺评**：默认按实际提交人数求平均。
5. **大众零票选手**：默认赋分 0 分。
6. **总成绩并列**：默认个人赛得分高者优先。
7. **域名与 HTTPS**：是否有域名？是否需要 HTTPS（投票页涉及密码条，建议 HTTPS）？若无域名，可用 IP 直连。
8. **服务器环境**：Linux 发行版 / 是否已装 Docker / 是否已有 Nginx 占用 80 端口 / 期待的部署方式（Docker 或原生 Node + systemd）。
9. **是否需要防刷**：是否有"同一 WiFi、同一公网 IP"的现实情况（现场手机可能共用出口 IP，因此不建议按 IP 做一人一票）。

## 第二部分：技术大纲

### 1. 技术栈选型

| 层 | 选型 | 理由 |
|---|---|---|
| 运行时 | Node.js 22 LTS（本地已 v24） | 轻量、单进程即可支撑本次规模 |
| 后端框架 | Fastify | 高性能、内置 schema 校验、插件生态干净 |
| 数据库 | SQLite（WAL 模式） | 零运维、单文件、事务可靠；本次规模（百级投票 × 两赛事）绰绰有余，可随时备份 |
| ORM/访问 | better-sqlite3（同步、事务安全） | 无迁移服务依赖，保证并发写入不丢票 |
| 模板/前端 | 服务端渲染（EJS/Handlebars）+ 原生 ES 模块 + 少量 Alpine.js | 无需构建步骤、首屏快、手机端友好、部署简单 |
| 样式 | 手写 CSS 变量 + 响应式栅格（或 Tailwind CLI 预编译） | 保持"简约美观"可控，避免大依赖 |
| 会话 | 签名 Cookie（@fastify/cookie + @fastify/session） | 无需 Redis |
| 密码哈希 | bcrypt | 管理员/密码条安全存储 |
| Excel 导出 | exceljs | 支持多 sheet、样式、中文列宽 |
| 图片处理 | sharp | 上传选手照片自动压缩/裁剪成统一比例缩略图 |
| 进程守护 | systemd（首选）/ pm2 | 开机自启、崩溃自动重启 |
| 反向代理 | Nginx（80 → 应用 8080） | 双端口访问、HTTPS 终止、静态资源加速 |
| 日志 | pino（应用日志）+ 数据库审计表（业务日志） | 排查与合规分开 |

> 备选：若服务器已有 Docker，则用单容器镜像部署（`node:22-alpine` + 卷挂载 SQLite 与上传目录），一条 `docker compose up -d` 完成，回滚方便。

### 2. 系统架构

```
        ┌──────────── 手机 / PC 浏览器 ────────────┐
        │                                          │
   80 端口                                  8080 端口
   (Nginx)                                 (直连应用)
        └───────────────┬──────────────────────────┘
                        ▼
              Nginx 反向代理 / TLS 终止
                        ▼
         Node.js + Fastify（127.0.0.1:3000 内部端口）
        ├── /vote/group        小组赛投票入口（密码条）
        ├── /vote/individual   个人赛投票入口（密码条）
        ├── /manage            后台管理（账号密码）
        ├── /api/*             内部接口
        └── 计分引擎（纯函数，可单测）
                        ▼
      SQLite（WAL） + data/uploads（选手图片） + logs/
```

**双端口方案说明**：应用只监听内部 3000（仅本机），由 Nginx 同时监听 **80** 与 **8080** 两个 server 块反代到同一应用 —— 两个端口访问到的是同一套系统、同一份数据，满足"页面同时开在 80 和 8080"。8080 也可作为现场备用入口（若 80 被占用或需绕过缓存）。

### 3. 数据模型（核心表）

```
players          id, no(序号), name, photo, tag, intro, active, sort_order
voters           id, name, role(public|pro), active, note        # 投票人名单
admins           id, username, password_hash, created_at
settings         key, value                                       # 密码条、开关、时间、权重、主题色
sessions         id, sid, role, voter_id, created_at, expire_at

# 赛事维度用 competition 字段区分：'group' | 'individual'（两套数据同表隔离，或分表）
votes            id, competition, voter_id, voter_name, ip, ua,
                 created_at, source(auto|manual), invalid, operator, note
vote_items       id, vote_id, player_id                           # 一条投票勾选的选手

scores           id, competition, judge_id, player_id, score,
                 created_at, updated_at, source(auto|manual), operator, note

results          id, competition, player_id, public_votes, public_rank,
                 public_points, pro_avg, competition_score, updated_at
final_results    player_id, group_score, individual_score,
                 total_score(×40%+×60%), final_rank, updated_at

audit_logs       id, at, actor_type, actor, action, target,
                 before_json, after_json, ip
```

- `competition` 字段贯穿投票与打分表，天然实现小组赛 / 个人赛**数据隔离**。
- 所有计分结果表为**派生数据**，任何变更后由计分引擎全量重算（幂等，避免增量误差）。

### 4. 计分引擎（纯函数 + 单元测试）

```
computePublicRank(votes)        → 票数 → 原始排名（并列规则可配）
rankToPoints(rank)              → 第1名10分 … 第10名1分
computeProAvg(scores, judges)   → 算术平均（缺评策略可配）
computeCompetition(...)         → 专业均分 + 大众赋分（上限110）
computeFinal(group, individual) → 小组×0.4 + 个人×0.6，总排名
```
- 纯函数、无副作用、输入输出可测 → 用 Node 内置 `node:test` 编写单元测试，覆盖：并列票、零票、缺评、上限封顶、并列总成绩。

### 5. 关键接口（节选）

```
POST /api/auth/login          密码条校验（普通用户）
POST /api/vote/group          提交小组赛投票（幂等、后端强校验最多3人）
POST /api/vote/individual     提交个人赛投票
POST /api/score/submit        专业评审提交打分
GET  /api/ranking/:competition  实时排名（投票页/公示页）

POST /manage/login            管理员登录
GET  /manage/*                后台页面
POST /manage/api/players      选手增删改 + 图片上传
POST /manage/api/manual-vote  手动赋分/补录（含改前改后预览）
POST /manage/api/toggle       开赛 / 截止 / 重开
POST /manage/api/recalc       强制重算
GET  /manage/api/export?type=full|rank|raw   导出 Excel
GET  /manage/api/logs         操作日志
```

- 各写接口均带：鉴权中间件 + 速率限制 + 服务端业务校验（前端置灰只是体验，不是防线）。
- 投票/打分提交在 SQLite 事务内完成，唯一索引 `(competition, voter_id)` 保证不重复。

### 6. 安全与可靠性

- 管理员与密码条均哈希存储；后台登录失败限流 + 锁定。
- 会话 Cookie：HttpOnly + SameSite，写操作校验 CSRF token。
- 后端强校验：赛事开启状态、时间窗、勾选人数上限、分数范围 0–100。
- 每日自动备份：SQLite `.backup` 或文件快照，保留最近 14 份；关键节点（开赛前/截止后）手动备份按钮。
- 数据修改全部留痕（审计表），支持导出与回滚参考。
- 输入转义，防 XSS；SQL 全部参数化。
- 应用仅监听 127.0.0.1，外部只能经 Nginx 访问。

### 7. 部署方案（拿到 SSH 后执行）

1. **环境探测**：确认发行版、Node 版本、端口 80/8080 占用情况、防火墙、是否已有 Nginx/Docker。
2. **目录规划**：`/opt/hostvote/{app,data,backup,logs}`，`data` 与 `backup` 独立于代码，便于升级。
3. **安装依赖**：Node 22 LTS（NodeSource 或 nvm）、Nginx、编译工具（better-sqlite3/sharp 可能需要）；若用 Docker 则只需 Docker。
4. **部署代码**：本地打包 → `rsync/scp` 上传（排除 node_modules）→ 服务器 `npm ci --omit=dev`。
5. **初始化**：生成 `.env`（会话密钥、管理员初始密码、端口）→ 执行建表与种子数据（10 位选手占位、4 位评审占位、示例密码条）。
6. **进程守护**：systemd unit（`hostvote.service`，开机自启、崩溃自拉起）。
7. **Nginx 配置**：`listen 80` 与 `listen 8080` 两个 server 块 → 反代 `127.0.0.1:3000`，透传真实 IP（`X-Forwarded-For`），配置静态资源缓存与上传大小限制。
8. **防火墙**：放行 80 / 8080（以及 443 若配 HTTPS），其余关闭。
9. **健康检查**：`/healthz`、三个入口页面 200 校验、端到端试投一遍（投票→打分→后台改数→重算→导出）。
10. **交付**：输出《部署报告》—— 访问地址（含两个端口的完整 URL）、后台地址与初始账号密码、密码条、备份路径、常用运维命令（重启/看日志/备份/恢复）。
11. **灰度演练**：先由你本人在真机（手机 + PC）走一遍全流程，确认无误后再发密码条给现场。
